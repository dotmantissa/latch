# Local workspace and Neon setup

The public introduction and readiness page lead to sign in, create a request, save a draft, reload it, revise it,
inspect saved version history and archive it. All saved state comes from the supplied
Neon Postgres database. The app starts with an empty request list and no admitted suppliers.
Light, Dark and System appearance follow the provided brand tokens.

Inspection is implemented and can be enabled by an operator with LATCH_ENABLE_INSPECTIONS=true, a working private supervisor channel and Vultr inference. The default remains disabled on a fresh checkout. Admitted source profiles must match the worker hash, be active and unexpired. Users acknowledge the public capture/inference disclosure before queue admission. Status, cancellation and reload recovery use durable jobs. See [deployment](DEPLOYMENT.md).

Individual review, comparison, approval, recheck and internal receipt workflows preserve unknown values. A supported page need not have a complete quote; incomplete evidence blocks approval.

## Start the workspace

```bash
bash scripts/bootstrap.sh
.venv/bin/python -m services.api.operator migrate
.venv/bin/python -m services.api.operator create-user --username dotmantissa --display-name dotmantissa
bash scripts/dev.sh
```

The account command reads the password twice from a terminal. Use 12 to 256 characters.
Open https://localhost:8443 and choose Open Latch; the workspace is /requests. Its development certificate is generated in
the ignored private directory; accept it in the local browser. Secure cookies are used
even for local development. The script builds the UI before starting one API process.
Stop the foreground process with Ctrl+C.

This checkout already has the supplied connection in private/database-url, with mode 0600,
and the latch schema has been migrated through version11 after an encrypted recovery
point and isolated restore verification. The public deployment now admits a reviewed source and creates isolated demonstration workspaces.
A fresh checkout needs its own private
connection file. LATCH_DATABASE_URL_FILE points at that file, and LATCH_PUBLIC_ORIGIN must
match the HTTPS origin used by the browser. No connection string belongs in Vite variables,
shell arguments, commits or screenshots. The session key is generated by the migration
command in private/csrf-key and must persist across server restarts.

The app uses the supplied pooled endpoint for requests and derives its corresponding
direct Neon endpoint for migrations. Both retain the connection's TLS options. Every
connection sets its schema and timeouts inside a transaction. Migrations are explicitly
run, serialized and checksum checked. They create only the latch schema and its objects.
Every applied checksum and contiguous migration version is checked at connection time.
Unknown versions stop startup; populated data requires a recovery point before a future
migration. Consistent encrypted logical backup and isolated restore are verified;
production cutover and provider point in time restore still need operator validation.

## Saved request behavior

Drafts allow one to three required items and zero to three admitted supplier pages. Each
item has private and public specification fields. Only public descriptions are sent to Vultr after the user acknowledges the disclosure. Budget entry uses USD decimal strings and exact integer cents.
Deadlines store the local entered time, IANA timezone and matching UTC instant. Ambiguous
clock changes require another explicit local time.

Saving creates an immutable version and a durable event. Edits use If-Match. A stale tab
gets a conflict with a Load latest version action. Save retries retain their intent key;
a dropped response cannot silently create a second request. Earlier versions remain
available. Archive retains this history and blocks later edits. It does not delete data.

No supplier is admitted by default. An operator may add a reviewed exact-path profile:

```bash
.venv/bin/python -m services.api.operator admit-profile --profile-file private/reviewed-profile.json
```

The file follows SourceProfile in services/common/source_policy.py. Admission validates
syntax, expiry and exact page scope. Real supplier compatibility, capture consent, network
isolation and inference checks are separate prerequisites before inspection is enabled.

Resetting a password is an operator terminal action and revokes that account's sessions:

```bash
.venv/bin/python -m services.api.operator reset-password --username dotmantissa
```

## Verification

```bash
.venv/bin/pytest
LATCH_TEST_DATABASE_URL_FILE=private/database-url .venv/bin/pytest --tb=short
.venv/bin/ruff check services tests scripts/check_browser.py scripts/check_repository.py
PATH="$PWD/.tools/node/node_modules/node/bin:$PATH" node .tools/node/node_modules/npm/bin/npm-cli.js run build
PLAYWRIGHT_BROWSERS_PATH=.tools/browsers .venv/bin/python -m playwright install chromium
PLAYWRIGHT_BROWSERS_PATH=.tools/browsers .venv/bin/python scripts/check_browser.py
.venv/bin/python scripts/check_repository.py
```

The first pytest command skips Neon integration checks unless explicitly configured.
Neon checks create uniquely named latch_test schemas and drop only their own schema on
completion. Interrupted test schema names remain under ignored var/test-schemas. Browser
checks create a separate temporary account/schema and HTTPS server on port 8444, exercise
actual HTTP saves, server restart, version conflicts, read only history, archive, session
expiry and theme behavior, then remove their schema and server afterward. Recovery IDs and private
screenshots are under var/browser-check. Assertion worksheets are test inputs, with no
supplier pages or fake offer results. They are never inserted into the application schema.

On minimal Linux installations Chromium needs its platform libraries. In this checkout
the missing Ubuntu libraries were downloaded and extracted under .tools/browser-libs;
prefix the browser command with
LD_LIBRARY_PATH="$PWD/.tools/browser-libs/usr/lib/x86_64-linux-gnu" to use them.
The browser checker also runs axe WCAG A/AA checks at 320 and 1440 pixels in both themes,
checks keyboard focus, reduced motion, 200 percent zoom and all six specified widths.
These local browser checks establish the saved draft flow, not isolated supplier execution.

Regenerate public TypeScript contracts from the actual FastAPI schemas after API edits:

```bash
PATH="$PWD/.tools/node/node_modules/node/bin:$PATH" node .tools/node/node_modules/npm/bin/npm-cli.js run contracts
```

The login throttle is bounded and process local. Keep one API process until a shared
limiter is implemented. Public deployment, buyer evaluation, production encrypted
volumes and retention consent remain future work in the implementation roadmap.
